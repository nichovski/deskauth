# Export accounts as otpauth links

**Date:** 2026-11-27 · **Branch:** feat/export · **Author:** Bogdan

## What it does

Settings > Export accounts writes every account to a plain-text file, one `otpauth://totp/` link per line.

- The user types the password again, even though the vault is unlocked. In "Password and YubiKey together" mode one registered key must be touched as well.
- A native save dialog opens. Cancel writes nothing.
- The file is created with mode 0600 on Unix. An existing file is replaced only after the dialog's own "Replace?" question, and the replacement is a new file, so an old file's wider mode is not kept.
- The UI shows `Saved to <path>. Delete it after the import.` and a warning that the file holds every secret in plain text.

## Why

To move 2FA codes from Deskauth into Bitwarden / Vaultwarden. A Bitwarden login's TOTP field accepts an `otpauth://` link, so plain links are the simplest format that works there. No other formats (JSON, CSV, QR) were added.

## How it works

- `src-tauri/src/export.rs` (new)
  - `uri(&Account) -> Zeroizing<String>` builds the link.
  - `export(state, password, emit, pick)` does, in order: take the ops lock (`commands::begin`), `verify_identity`, `pick()` (the save dialog), build the text under the vault mutex, release the mutex, `vault::write_atomic`. A wrong password stops before the dialog opens.
- `unlock_commands::verify_identity`: Password and Any modes re-open the file with `vault::unlock` (the copy is dropped at once). PasswordYubikey mode uses the existing `verify_two_factor` (password + one touch).
- `commands::vault_export` runs `export` inside `blocking()` and passes a picker that calls `tauri-plugin-dialog`'s `blocking_save_file` from Rust. The plugin moves the dialog to the main thread itself (`run_on_main_thread`).
- `vault::write_atomic` became `pub(crate)`: temp file with `create_new` and mode 0600, fsync, rename over the target.
- Secrets stay in Rust (`Zeroizing`). JavaScript sends the password and gets back only the saved path, or null on cancel.
- The plugin is registered in Rust only. The capability file gets no `dialog:*` permission and there is no npm dialog package, so the web view cannot open a dialog or choose where secrets are written.

### Link format

```
otpauth://totp/{issuer}:{name}?secret={S}[&issuer={issuer}]&algorithm={SHA1|SHA256|SHA512}&digits={d}&period={p}
```

- Issuer and name are percent-encoded except RFC 3986 unreserved characters. '+' becomes `%2B`, because the parser form-decodes query values, where a bare '+' means a space.
- The label is always `issuer:name`, also `:name` when the issuer is empty. A plain `name` label would split on a ':' in the name, and the url crate removes a `.` or `..` path segment (even as `%2e`).
- `issuer=` is written only when the issuer is not empty. Algorithm, digits and period are always written.
- Tests in `export.rs` run a table of tricky names (spaces, `: & = % + # / ?`, `%41`, `/a/../b`, non-ASCII, empty issuer, `..`, all algorithms, 8 digits, period 60) through `migration::parse_uri` and compare every field.

### Rejected options

- Dialog plugin from JavaScript: needs an npm package and a capability, and then a command would write secrets to any path the web view names.
- Fixed path such as `~/Downloads/deskauth-export.txt`: no dependency, but Downloads is often synced, and the user could not choose.
- `rfd` or `gtk` directly: what the plugin already wraps, with the main-thread rules to handle ourselves.
- Blob download from JavaScript: secrets in the web view and a 0644 file.
- Separate "verify" and "export" commands: the vault could change or lock between the two calls.

## Review

Reviewers: GLM-5.3 Flash and DeepSeek V4 Flash (pi, high thinking), GPT-6.1 Sol (Codex, medium). GPT-6.2 Sol was not available in Codex.

Rejected:
- "The blocking dialog on a worker thread hangs on macOS/Linux": the plugin dispatches to the main thread (`tauri-plugin-dialog` `desktop.rs`, `run_on_main_thread`).
- "Rename over an existing file fails on Windows": `std::fs::rename` replaces the target on Windows.
- "A '+' in the secret is corrupted": secrets are base32 and have no '+'.

Won't fix:
- Windows: the file gets the folder's inherited ACL, not a private one. `vault.json` is written the same way.
- If fsync of the parent directory fails after the rename, the export reports an error although the file exists. Needs unusual directory permissions.
- Leading or trailing spaces in a name are trimmed when a link is parsed back. Names get such spaces only from a Google migration import; fixing it means changing import, which was out of scope. Bitwarden reads the issuer from the query anyway.
- The password stays in the field after an error, like the change-password card, so a typo can be fixed.
